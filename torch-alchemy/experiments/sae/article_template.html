Sentiment Features in a Tiny Review Model

Decomposing a small transformer trained only to predict the next token of movie reviews into sparse, interpretable features — and using them to steer what it writes.

A language model trained only to predict the next token of movie reviews never sees a label saying whether a review is positive. Yet to predict well it helps to know: "the acting was superb, the plot…" continues differently from "the acting was wooden, the plot…". OpenAI's sentiment neuron found exactly this: a next-character model trained on Amazon reviews had one unit that tracked sentiment on its own [1]. Our workshop asks the same question of a much smaller model, and a linear probe (a weighted sum of the model's numbers, fitted on labelled sentences) shows that its activations do contain sentiment.

But a probe only shows that sentiment can be read off. To understand what the model itself represents, we would like to look at its internal units and see what each means. The natural unit, a single number in a layer's activations (a neuron, or here a dimension of the residual stream — the vector each layer reads from and adds to), turns out to be a poor one: units are usually polysemantic, responding to many unrelated things. One explanation is superposition: a model can represent more features than it has dimensions by giving each feature its own direction, a combination of many dimensions, and relying on most features being inactive at any moment [2].

If that is right, the features can be recovered by dictionary learning: rewriting each activation vector as a sparse combination of many more directions than it has dimensions. Anthropic showed that a sparse autoencoder (SAE) does this well [2]; we use the TopK variant, which keeps exactly the k largest features per token [3]. In this report we train one on the residual stream of a trained microgpt model, look closely at a few sentiment features — what they fire on, what they make the model say, and whether any single dimension does the same — then look at all features at once. Everything below comes from held-out IMDB tokens the model never trained on. The features discussed by number (#904, #1067, #1241) are those of the example model this page was written for; an SAE on another model finds similar features under other numbers.

Summary of Results

  • The SAE reconstructs the layer faithfully. It explains of the activations' variance with active features per token, and with its reconstruction in place of the layer the model keeps of its performance; none of its features is dead.
  • Some features are clearly about sentiment. Feature #904 fires on warm praise: alone it tells positive SST sentences from negative ones of the time, and of the tokens where it fires most come from positive reviews. #1067 fires on "poorly", "dull" and "uninteresting"; #1241 on approving adjectives like "solid" and "excellent".
  • These features are invisible in the dimensions. The best single residual-stream dimension manages only on SST; features beat 60% against dimension. The dimension most correlated with #904 is barely related to sentiment.
  • Features steer the model. Clamping #904 to its usual maximum turns a negative continuation into "superb … great performances"; clamping #1067 can make it complain that "the dialog was so flat". Above about 2× the text breaks down.
  • Sentiment is spread over many features. A probe on all the SAE's features reaches on SST dev, against on the raw activations of the same layer.

Problem Setup

We decompose the residual stream after layer of of the model. It is the place where every layer's contribution is summed, and late enough to hold sentiment (the probe reads the last layer):

How can we tell it works?

As in the original work, no single number settles it; we use three. The SAE explains of the variance of activations it never trained on. Replacing the layer's output by the SAE's reconstruction raises the model's next-token loss only a little: measured against replacing the layer by its average (which destroys it), of the loss is recovered. And features are dead (never fire). Finally, of course, the features have to make sense, which is what the rest of this report examines.

Detailed Investigations of Individual Features

For each feature we ask the questions the original paper asked, as far as our data allows: does it fire specifically on what we think, does it cause the matching behaviour downstream, and is it something a single dimension already does? Our proxy for sentiment — a cheap, independent signal to check the feature against — is the label of the review each token belongs to: of our tokens come from positive reviews. It is coarse (a negative review still praises some things), so we expect leaks.

Feature #1067: "poorly", "dull", "uninteresting"

#1067 is rarer ( of tokens) and fires on the words of a weak review: "trite and melodramatic", "dull & drab", "poorly written". Alone it scores on SST, for negative sentiment.

Only of its activations come from positive reviews, and of its strongest 1%. That is a weaker split than #904's, and here the coarse proxy shows: the feature fires on a word ("forgettable", "far below the standard", "worst"), and positive reviews use such words too, for instance about other films. The examples show it tracks the word's negativity, not the review's verdict.

Feature #1241: approving adjectives

#1241 fires on adjectives of approval — "solid", "excellent", "brilliant", "perfect" — and alone scores on SST. Its strongest activations are on "solid" itself, as in "a solid performance".

Global Analysis

Are these three cherry-picked? For every feature and every residual-stream dimension of the same layer, we measure how well it alone separates positive from negative SST sentences (its maximum over a sentence's tokens, split halfway between the two classes' averages on train, scored on dev).

Most features are not about sentiment at all — they track words, punctuation and phrasing, as the browser below shows — but the sentiment ones stand out far more than any dimension. Sentiment is also spread across many features: an L1-regularised probe on all SAE features reaches on SST dev, against on the raw activations.

Limitations

  • The model is tiny ( layers, trained only on movie reviews) and we study one layer; many features are messier than in the papers, and some are not interpretable at all.
  • The sentiment proxy is the review's label, so a feature for negative words in a positive review counts against it. Labels in the browser are automatic.
  • Examples come from held-out tokens, so very rare features show few.
  • Downstream effects through the output layer skip the last decoder layer, so they are approximate; the steering samples are the direct test.

Related Work

We follow Anthropic's Towards Monosemanticity [2], which decomposed a one-layer transformer's MLP with a sparse autoencoder, closely in method and presentation; Golden Gate Claude applied feature clamping at scale. The TopK SAE is from Gao et al. [3]. The question itself comes from the sentiment neuron [1].

How to reproduce

# from torch-alchemy/, with a trained model
python3 -m experiments.sae.train   checkpoint=<model.safetensors>           # train the SAE (about 1 minute)
python3 -m experiments.sae.article checkpoint=<model.safetensors>           # this page: runs/sae/index.html
python3 -m experiments.sae.serve   checkpoint=<model.safetensors>           # the page plus live steering
python3 -m experiments.sae.steer   checkpoint=<model.safetensors> clamp.904=1 prompt='this movie'  # in a terminal

The explorer's built-in samples are precomputed; your own prompts and any feature need a live model (serve or steer).
